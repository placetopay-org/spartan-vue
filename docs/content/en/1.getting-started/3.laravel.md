In a Laravel project with Inertia, Vue lives inside `resources/js` and Vite compiles the assets. Spartan integrates like any other Vue dependency: the difference is **where** to place the stylesheet and **where** to register the i18n plugin.

## Requirements

- **Laravel** `11` or `12` with Vite
- **Inertia** with the `@inertiajs/vue3` adapter
- **Vue** `^3.5`
- **TailwindCSS** `^4` through the `@tailwindcss/vite` plugin
- **Node.js** `20.19` or `^22.12`

::prose-tip
The official starter kits (`laravel new` choosing Vue) already ship Inertia, Vue 3, TailwindCSS v4 and SSR configured. If you start from one of them, you only need the steps in this guide.
::

## Step-by-step installation

::steps
### Install the packages

Spartan is installed as a dev dependency. `vue-i18n` is a **required peer dependency**: components with internal text rely on it to resolve their translations.

::::code-group

```bash [npm]
npm install -D @placetopay/spartan-vue
npm install vue-i18n
```

```bash [pnpm]
pnpm add -D @placetopay/spartan-vue
pnpm add vue-i18n
```

```bash [yarn]
yarn add --dev @placetopay/spartan-vue
yarn add vue-i18n
```
::::

You do not need to install `@tailwindcss/forms` or `vue-sonner`: both are direct dependencies of Spartan and resolve on their own.

### Configure the styles

Laravel centralizes styles in `resources/css/app.css`. Add the Spartan `@import` right after the TailwindCSS one:

```css [resources/css/app.css]
@import 'tailwindcss';
@import '@placetopay/spartan-vue/styles.css';

@source '../js/**/*.{vue,js,ts}';
@source '../views/**/*.blade.php';
```

::prose-warning
`@source` paths are **relative to the CSS file**, not to the project root. From `resources/css/` the path to your Vue components is `../js/`.
::

::prose-tip
You do not need a `@source` pointing at `node_modules`. Spartan's stylesheet already declares the scanning of its own compiled files internally, so its classes are generated automatically.
::

If your project comes from a starter kit, `app.css` likely already includes equivalent globs (`@source '../**/*.vue'`). In that case, adding the Spartan `@import` is enough.

### Register vue-i18n in the entry point

Inertia's entry point is where the Vue instance is created, so that is where the i18n plugin gets registered:

```ts [resources/js/app.ts]
import '../css/app.css';

import { createInertiaApp } from '@inertiajs/vue3';
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers';
import { createApp, h, type DefineComponent } from 'vue';
import { createI18n } from 'vue-i18n';
import { addSpartanAllMessages } from '@placetopay/spartan-vue/i18n';

const i18n = createI18n({
    legacy: false,
    locale: 'en',
    fallbackLocale: 'es',
    messages: addSpartanAllMessages({}),
});

createInertiaApp({
    resolve: (name) =>
        resolvePageComponent(
            `./pages/${name}.vue`,
            import.meta.glob<DefineComponent>('./pages/**/*.vue'),
        ),
    setup({ el, App, props, plugin }) {
        createApp({ render: () => h(App, props) })
            .use(plugin)
            .use(i18n)
            .mount(el);
    },
});
```

::prose-warning
`legacy: false` is mandatory. Spartan components use `useI18n()` from the Composition API; with legacy mode enabled the internal texts are left untranslated.
::

`addSpartanAllMessages({})` returns Spartan's five languages ready to use. To merge them with your own translations, pass them as an argument:

```ts [resources/js/app.ts]
import en from './lang/en.json';
import es from './lang/es.json';

const i18n = createI18n({
    legacy: false,
    locale: 'en',
    fallbackLocale: 'es',
    messages: addSpartanAllMessages({ en, es }),
});
```

### Use the components

Components are imported directly in your Inertia pages:

```vue [resources/js/pages/Dashboard.vue]
<script setup lang="ts">
import { ref } from 'vue';
import { router } from '@inertiajs/vue3';
import { SButton, SInputBlock } from '@placetopay/spartan-vue';

const name = ref('');

const submit = () => router.post('/teams', { name: name.value });
</script>

<template>
  <form @submit.prevent="submit">
    <SInputBlock v-model="name" label="Team name" />
    <SButton type="submit">Create</SButton>
  </form>
</template>
```
::

::prose-tip
If your pages live in `resources/js/Pages` (capitalized, the Laravel Breeze convention), adjust the `resolvePageComponent` and `@source` globs accordingly.
::

## Vite configuration

For all of the above to work, `vite.config.ts` must load the Laravel, TailwindCSS and Vue plugins, and include the stylesheet among the compiled assets:

```ts [vite.config.ts]
import tailwindcss from '@tailwindcss/vite';
import vue from '@vitejs/plugin-vue';
import laravel from 'laravel-vite-plugin';
import { defineConfig } from 'vite';

export default defineConfig({
    plugins: [
        laravel({
            input: ['resources/js/app.ts'],
            ssr: 'resources/js/ssr.ts',
            refresh: true,
        }),
        tailwindcss(),
        vue(),
    ],
});
```

## Server-Side Rendering

If your application uses SSR, the server entry point creates its own Vue instance, so it must register the i18n plugin as well:

```ts [resources/js/ssr.ts]
import { createInertiaApp } from '@inertiajs/vue3';
import createServer from '@inertiajs/vue3/server';
import { resolvePageComponent } from 'laravel-vite-plugin/inertia-helpers';
import { renderToString } from '@vue/server-renderer';
import { createSSRApp, h, type DefineComponent } from 'vue';
import { createI18n } from 'vue-i18n';
import { addSpartanAllMessages } from '@placetopay/spartan-vue/i18n';

createServer((page) =>
    createInertiaApp({
        page,
        render: renderToString,
        resolve: (name) =>
            resolvePageComponent(
                `./pages/${name}.vue`,
                import.meta.glob<DefineComponent>('./pages/**/*.vue'),
            ),
        setup({ App, props, plugin }) {
            const i18n = createI18n({
                legacy: false,
                locale: 'en',
                fallbackLocale: 'es',
                messages: addSpartanAllMessages({}),
            });

            return createSSRApp({ render: () => h(App, props) })
                .use(plugin)
                .use(i18n);
        },
    }),
);
```

::prose-warning
Create the `createI18n` instance **inside** `setup`, not at module level. In SSR the process serves multiple requests, and a shared instance leaks one user's language into another's.
::

## Dark mode

Spartan enables dark mode with the `.dark` class strategy. Add it to the root element of your Blade template:

```blade [resources/views/app.blade.php]
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}" class="dark">
<head>
    @vite(['resources/js/app.ts', 'resources/css/app.css'])
    @inertiaHead
</head>
<body>
    @inertia
</body>
</html>
```

To toggle it at runtime, add or remove the `dark` class on `document.documentElement`.

## Theme customization

The primary palette is overridden with CSS variables inside `@theme`, always **after** the Spartan `@import`:

```css [resources/css/app.css]
@import 'tailwindcss';
@import '@placetopay/spartan-vue/styles.css';

@source '../js/**/*.{vue,js,ts}';
@source '../views/**/*.blade.php';

@theme {
  --color-spartan-primary-50:  rgb(228 242 253);
  --color-spartan-primary-500: rgb(33 150 243);
  --color-spartan-primary-900: rgb(13 42 84);
}
```

See the [installation guide](/en/getting-started/installation) for the full palette and for excluding the Inter font.

## Common issues

### Styles are not applying

Check that `resources/css/app.css` is declared in the `@vite` directive of your Blade template **and** that the `@source` globs cover `resources/js`. Remember those paths are relative to the CSS file.

### Classes appear in development but not in production

Vite purges undetected classes at build time. If a component receives classes built dynamically in PHP or Blade, add a `@source` covering those files, or declare the classes with `@source inline(...)`.

### Component internal texts are not translating

Confirm the i18n plugin is registered in `app.ts` (and in `ssr.ts` if you use SSR) and that `legacy` is set to `false`. More detail in the [i18n guide](/en/getting-started/i18n).

### Resolution errors with pnpm

Since `3.0.0-beta.17` Spartan declares all of its dependencies, so it works with pnpm's strict `node_modules`. If you are pinned to an older version, add `shamefully-hoist=true` to your `.npmrc`.
